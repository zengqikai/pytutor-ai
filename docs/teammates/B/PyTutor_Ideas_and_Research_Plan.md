# PyTutor 构思记录：工程改造思路 + 科研方向分析 + 研究计划

> 本文档记录整个讨论过程中形成的解决构思与科研方向判断，与《PyTutor 问题清单》配套（问题清单只记问题，本文只记构思）。
> 硬约束：① 真实学生数据难获取（能否拿到待定）；② 11 月初需完成项目初期；③ 不动现有大框架，只在其上修改。

---

## 第一部分：工程改造构思（核心：分层 + 架桥，不重构）

### 1.1 总原则：换零件，不换车

现有骨架「诊断 → 策略 → 生成 → 画像 → RAG」恰好就是文献中先进方法所需要的结构（KELE 的 consultant–teacher、StratL 的状态→意图→生成，本质是同一条链）。因此所有改进都定位为「某个 service 内部的实现升级」或「旁挂新模块」，不改数据流主干。

**重构红线（碰了就是伤筋动骨，避开）：**
1. 不拆微服务；
2. 不改「诊断→策略→生成→画像」的主干顺序；
3. 多 agent 若要做，作为新节点挂进现有 LangGraph 图，不重写整张图；
4. 不动认证、数据库、RAG 等已能跑的基础设施。

### 1.2 构思一：三层诊断架构（解决覆盖不全 A1、权重隐形 D1）

不再纠结「M1–M8 够不够全」，改为分层，上层精确、下层兜底：

```
第 0 层：知识点掌握度          ← 完整，永不漏。每道题对应知识点，失败即降掌握度（已有）。
第 1 层：错误大类（读报错类型）  ← 完整但粗。Python 报错自带分类：NameError / TypeError /
                                IndexError / KeyError…；加一条「跑完但输出不对」= 逻辑错误。
第 2 层：M1–M8 具体误区        ← 精确但不完整。认得出加细节，认不出不影响大盘。
```

权重与路径建在第 0、1 层（完整层）上；M1–M8 只作精修层。第 1 层几乎免费（读 stderr 即得）。

### 1.3 构思二：根因层（解决只看症状 A2）

在 M（症状）之上建一小组根因，一根多症。例如：
「值不会自动留存」→ M3（append 返 None）+ M6（print ≠ return）；「计数从哪到哪的偏差」→ M4 + M5；「程序状态如何随循环推进」→ M8 + 部分 M5。

**前提**：这张「根因→症状」映射是假设，不能写死，需用真实共现数据验证后再固化。文献支撑：McMining / KC-Finder / SANN 一整条「基于 AST 从数据自动发现误区与知识成分」的研究线，与项目现有 AST 投入同源。

### 1.4 构思三：真置信度 + 知识追踪权重（解决 A3、B1）

三步：① 把硬编码的置信度（0.85 / 0.5）换成基于证据计算的真分数；② 对知识点 / 根因维护掌握概率，逐次证据更新并加衰减；③ 权重 = 未掌握概率 × 基础重要度，决定教什么、教多深、何时撤支架。前置：必须先修好 `has_history` 硬编码短路。文献结论：专用知识追踪小模型（如 Code-DKT）在成本、延迟、准确率上优于用 LLM 做知识追踪。

### 1.5 构思四：给「诊断」与「路径」架桥（解决 B2、B3）

让误区 / 根因诊断结果回流路径：更新权重 → 在薄弱知识点插针对性微课 / 换教法 / 决定前进还是重练。路径从「15 步死顺序」变为「按权重动态选下一步 + 先修关系约束」。文献蓝图：StratL 的 Pedagogical Steering（学生状态追踪 → 教学意图转移图 → 按意图生成）。

### 1.6 构思五：多 agent（可选进阶）

最小有价值版本 = 对抗（AST + 沙箱，符号化、便宜）+ 教学 + 批评（换模型，避免自己批自己）三个角色，挂进现有图。不做无界辩论循环（延迟灾难）。

### 1.7 构思六：对抗式教学的诚实定位

剥掉包装后唯一真有价值的是「先让学生预测，再运行揭晓」（预测—观察—解释；hypercorrection 效应），学理正名是 Productive Failure，不叫「对抗」。不当核心卖点，作为小机制保留。

### 1.8 构思七：工程与安全修复（发布前必做，全部是局部改动）

统一代码执行入口并强制 Docker 隔离；SECRET_KEY 占位符则拒绝启动；`open()` 默认禁止；LLM 故障用 AST 诊断兜底；RAG 加熔断；评测集补对抗负例并报混淆矩阵。

### 1.9 推进顺序

地基（修 `has_history`、真置信度、安全三件套）→ 骨架（第 1 层错误大类 + 权重底座）→ 血肉（架桥、根因层）→ 锦上添花（多 agent、predict-then-run）。

## 第二部分：科研方向分析

### 2.1 「站得住脚」的标准

本科层级现实可发的贡献只有三类：① 数据集 / 基准；② 聚焦的实证发现；③ 窄的方法增量。「我搭了个 X 系统」「我把 Y 方法用上了」都站不住；必须是「我发现了 Z」或「我构建了数据集 W」。现实投稿层级：poster / short paper / workshop / arXiv 预印。

### 2.2 红线区（已被占或属工程，不能当科研点）

| 方向 | 状态 | 占据者 / 原因 |
|---|---|---|
| 误区感知型 tutor | 已占 | MisconceptionTutor（SIGCSE 2026） |
| 用 AST 增强误区诊断（裸命题） | 已占 | KC-Finder、Hoq、SANN 等整条线 |
| 多 agent 苏格拉底 tutor | 已占 | KELE（EMNLP 2025） |
| 知识追踪（裸命题） | 已占 | Code-DKT 等；且专用 KT 模型优于 LLM |
| 对抗式教学 | 本质是判题 | 除非转世为 predict-then-run 实证（绿-4） |
| **答案泄露 / tutor 过度帮助基准** | **已占（本次新核查）** | Maurya 2025 八维评测分类已含答案泄露维度；Macina 2023 测得 ChatGPT 66% 交互泄露答案；2026 年 4 月 arXiv 2604.18660 已做「对抗学生攻击下的答案泄露鲁棒性」完整基准 + 防御 |
| 分层架构 / 修 bug / RAG 调优 | 工程 | 非科研 |

### 2.3 绿区总览与约束筛选

| 方向 | 要真实学生数据 | 要人实验 | 11 月前可行 |

在「数据难拿 + 11 月初完成」双约束下，**主线锁定绿-2**。绿-1/3/4 保留为「若后续拿到数据 / 时间」的备胎。

## 第三部分：主线研究计划（绿-2）

### 3.1 研究问题

当 LLM 解释「学生代码里是什么误区、为什么」时，其解释中有多少断言是代码里真实存在的（AST 可证实），多少是幻觉？将 AST 结构证据先注入 prompt，能降低多少幻觉率？

一句话：**用不会撒谎的 AST 当符号裁判，量化 LLM 误区解释的忠实度，并检验证据注入的缓解效果。**

### 3.2 与已有工作的差异点（必须立住的 delta）

不是「又一篇 faithfulness」，而是「**符号化 AST 裁判 vs 纯文本裁判，用于编程误区诊断解释**」。动机有现成文献背书：Mitton 2026 指出 LLM 会幻觉误区、显式建模优于纯 LLM；McMining 附录分析了模型在纯正确代码上的系统性假阳性模式（如把低效写法误判为误区）。

### 3.3 方法框架

```
一段带已知误区的代码
   ├─ AST 分析 → 客观结构事实集（如「第 3 行 append 返回值被赋给 x」）
   └─ LLM 解释 → 拆分为原子断言（claim）
                     ↓
        逐条核对：每个断言在 AST 事实集中有无支持
        有 = 忠实断言；无 = 幻觉断言
   忠实度 = 被支持断言比例；另报幻觉类型分布（按 M 类、按断言类型）
```

对比条件（最小实验矩阵）：
- C1 纯 LLM 解释（基线）；
- C2 AST 证据注入后的 LLM 解释；
- （可选）C3 不同模型对比（DeepSeek vs 另一模型）。

### 3.4 时间线（现在 → 11 月初，8–10 周）

| 阶段 | 时长 | 内容 |
|---|---|---|
| 一 | 2–3 周 | 评测集扩建至 ~150–200 条「代码 + 误区标签 + AST 应有证据」，以现有 50+20 例为种子；决定手工构造还是 LLM 辅助生成 + 人工筛 |
| 二 | 2–3 周 | 定义忠实度指标；写「解释 → 原子断言 → AST 核验」脚本 |
| 三 | 2 周 | 跑 C1/C2（/C3）对比实验 |
| 四 | 2 周 | 人工抽查校验（1–2 人）确认自动判定与人一致；写作初稿 |

### 3.5 风险与对策

- 断言拆分本身要用 LLM，可能引入误差 → 人工抽查校验这一步不可省；
- AST 事实集覆盖不了的断言类型（如关于「学生意图」的断言）→ 明确划出「可核验 / 不可核验」两类，只对可核验类计忠实度，论文里如实说明；
- 评测集若含 LLM 生成样本，需防「同源偏置」（用 A 模型生成、又用 A 模型解释）→ 生成与被测模型分离。

## 第四部分：本次新增方向探讨（含新颖性核查结果）

核查结论先行：在双约束下，**没有发现比绿-2 更好的独立新方向；但存在三个可并入绿-2 的「增厚子实验」和两个风险不同的备选独立方向**。

### 4.1 增厚绿-2 的三个子实验（推荐，同一套评测集复用）

**子实验 A：对抗负例下的假阳性研究（precision 视角）。**
在评测集中加入「接近误区但完全正确」的 hard negatives（如合法的 `while stack: stack.pop()`、正确的字典遍历），测 LLM / regex / AST 三通道各自的假阳性率与幻觉模式。
新颖性：部分被占——McMining 附录已分析纯正确代码上的假阳性模式；2026 年一篇期刊论文已测得 GPT-4 检测错误心智模型呈「高敏感低精确」（Precision 0.24，即四次报警仅一次为真）。**因此不宜做独立论文，但作为绿-2 的一个实验章节非常合理**：它直接源于项目里已复现的假阳性（问题清单 A4），且顺手修复评测诚信问题（E5）。

**子实验 B：RAG 接地消融。**
同一解释任务，对比「无检索 / 挂上现有 RAG 检索教材片段」两种条件下的忠实度变化。回答「检索接地能否减少误区解释幻觉」。零新基建（复用项目现成 RAG），给论文加一个有实用价值的维度。

**子实验 C：中英双语维度。**
同一批代码，分别要求中文解释与英文解释，比较忠实度差异。中文编程教育语境的 LLM 评测很少，这一维度成本极低（同一评测集跑两遍），且与「面向中文初学者」的项目定位天然一致。

三个子实验共用第三部分的评测集与核验脚本，边际成本低；合起来能把绿-2 从「单一发现」加厚成一篇更扎实的论文。

### 4.2 备选独立方向一：五级提示遵循度审计（风险：中高，谨慎）

研究问题：要求 LLM 按 Level 1–5 给提示时，它实际给出的信息量是否遵循约束？是否系统性「超级别泄露」（要求 Level 1 却给出 Level 3 的信息）？
新颖性核查：答案泄露作为二元问题已被重度占据（Maurya 八维分类、Macina 66% 泄露率、2026 年对抗学生攻击基准）。**「分级遵循度」这个细粒度角度尚未见直接工作，但离已占领域太近**，审稿人很容易问「和答案泄露评测差在哪」。若做，必须把 delta 严格限定为「渐进提示体系的逐级信息量校准」，且建议只作为 workshop 短文目标。综合判断：可做但不如 4.1 稳。

### 4.3 备选独立方向二：三通道诊断的成本—延迟—准确率系统比较（风险：低，但天花板低）

用同一评测集系统比较 regex / AST / LLM 三通道（及其组合）的准确率、假阳性、延迟、金钱成本，报完整混淆矩阵。
判断：完全离线、零新基建、必然做得完；但性质偏「经验报告 / 系统评测」，天花板是 poster 或经验类短文。适合作为**保底方案**：若绿-2 中途受阻，这份比较本身也能成文，且其数据就是绿-2 阶段一、二的副产品。

### 4.4 结论与推荐组合

**推荐：绿-2 主线 + 子实验 A（必做，源于自家真实发现）+ 子实验 B 或 C（选一，看时间）；4.3 作为保底副产品自然沉淀。** 4.2 仅在前述全部顺利、且能找到导师把关 delta 时再考虑。

这样一篇论文的骨架是：一个评测集（含 hard negatives）+ 一个核验方法（AST 符号裁判）+ 三组发现（幻觉率与类型、证据注入的缓解、假阳性模式），全部离线、零学生数据、零重构，11 月初可出初步版本。
