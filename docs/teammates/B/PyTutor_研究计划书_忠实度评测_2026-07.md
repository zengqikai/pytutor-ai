> 项目：PyTutor（本科毕业设计）· 研究子课题
> 撰写日期：2026-07-26 · 目标节点：2026-11 月初完成初步研究成果
> 状态：方向已通过新颖性核查（红线区排除见附录 A），基础设施已就位（`research/faithfulness/`）

## 1. 研究问题（一句话）

**当 LLM 向初学者解释"你的代码里存在什么误区、为什么"时，解释中有多少断言是代码里
真实存在的（AST 可证实），多少是幻觉？将 AST 结构证据先注入 prompt，能降低多少幻觉率？**

拆成三个可回答的子问题：

- RQ1：LLM 误区解释的**忠实度基线**是多少？幻觉断言的类型分布是什么（虚构代码结构 / 张冠李戴误区 / 无中生有的意图归因）？
- RQ2：**AST 证据注入**（把符号化结构事实放进 prompt）能带来多大的忠实度提升？
- RQ3：在**hard negatives**（结构酷似误区但完全正确的代码）上，LLM / 规则 / AST 三通道各自的假阳性率与幻觉模式如何？

## 2. 为什么这个点"站得住"（对导师的论证）

本科层级现实可立住的贡献只有三类：**数据集/基准、聚焦的实证发现、窄的方法增量**。
本课题同时提供三者：

1. **一个基准数据集**：150–200 条（代码，误区标签，应有 AST 证据，类别 ∈ {positive, hard_negative, clean}），含许可证逐条留存与可再分发闸门；
2. **一个核验方法**：LLM 解释 → 原子断言拆分 → 与 AST 事实集逐条核对的自动协议，明确划分"可核验/不可核验"断言；
3. **三组实证发现**：忠实度基线与幻觉类型分布（RQ1）、证据注入的缓解量（RQ2）、假阳性模式（RQ3）。

**与已有工作的 delta**：不是"又一篇 LLM faithfulness"——差异点是**符号化 AST 裁判 vs
纯文本裁判，应用于编程误区诊断解释**这一未被直接占领的窄口。动机有文献背书：
Mitton et al. 2026 指出 LLM 会幻觉误区、显式建模优于纯 LLM；McMining（arXiv 2510.08827）
附录分析了模型在纯正确代码上的系统性假阳性；2026 年期刊工作测得 GPT-4 检测错误心智模型
"高敏感低精确"（Precision 0.24）。这些工作都**没有**用符号裁判做逐断言核验。

**可行性硬约束全部满足**：纯离线、零真实学生数据、零人体实验、零系统重构；
项目已有对称双通道（AST 符号证据 + LLM 自然语言解释），改造成本极低。

## 3. 方法框架

```
一段带已知标签的代码
   ├─ AST 分析 → 客观结构事实集 F（如「第2行：append 返回值被赋给 x」）
   └─ LLM 解释 → 原子断言集 C = {c₁, c₂, …}（LLM 拆分 + 规则式拆分器双轨）
              ↓
   每条 cᵢ 判定：SUPPORTED（F 中有依据）/ CONTRADICTED（与 F 冲突）
               / UNVERIFIABLE（意图类断言，AST 原则上不可证）
   忠实度 = |SUPPORTED| / |SUPPORTED ∪ CONTRADICTED|   （只对可核验类计）
   另报：幻觉类型分布（按 M 类 × 断言类型交叉）
```

实验矩阵（最小可发表版本）：

| 条件 | 说明 |
|---|---|
| C1 | 纯 LLM 解释（基线） |
| C2 | AST 证据注入后的 LLM 解释（复用项目已接线的锚定 prompt） |
| C3（可选） | 换模型对比（DeepSeek vs 另一家，生成与被测分离防同源） |
| 子实验 A（必做） | hard negatives 上三通道假阳性率 + 幻觉模式 |
| 子实验 B/C（二选一，看时间） | RAG 接地消融 / 中英双语忠实度差异 |

**方法学纪律（防审稿人一击）**：
- **预注册**：忠实度指标定义、断言判定规则在跑任何实验前冻结并存档（本文档 + git 时间戳）；
- **同源偏置**：数据集若含 LLM 生成样本，生成模型 ≠ 被测模型；
- **人工校验**：断言拆分与自动判定各抽 30 例人工核对，报告一致率（目标 ≥85%），
  低于阈值则修判定规则重跑；
- **循环论证规避**：AST 事实集来自我方 visitor，核验 LLM 解释合法；但**不得**用它
  反证 visitor 自身正确性——后者只能靠独立构造的 hard negatives。

| Schema | `research/faithfulness/eval_sample.py` 的 EvalSample（含 category / origin_label / license） |

beyond-M 样本不是脏数据：它量化"M1–M8 覆盖了多少、漏了多少"，直接写进论文动机。

## 7. 风险与诚实边界

- 断言拆分本身用 LLM → 双轨（规则式拆分器兜底）+ 人工抽查；
- AST 覆盖不了"意图类"断言 → 划入 UNVERIFIABLE，不计入忠实度，论文如实说明；
- 内部 50+20 评测集与检测器同源 → 论文中一律表述为"内部一致性"；泛化声明只基于
  新建的、来源分离的 150–200 条集；
- 投稿定位：workshop / short paper / poster / arXiv 预印，不虚标目标。
