# C 方向 Task 2：Rubric 细化 — 实现文档

## 概述

将 Task 1 的泛用 5 维 Rubric 升级为行为锚定增强版，引入 Few-shot 校准、Chain-of-Thought 推理、证据锚定和误区特定指导。

**目标指标**：评分方差降低 → 维度分歧度 (mean dim range) < 0.5

## 四项增强 (文献驱动)

### 1. 行为锚定 (Behavioral Anchors)
**文献**：Rulers (2025) — rubric 应作为可执行规范，每级用可观测行为定义

V1 问题：
```
3分: "部分遵循，有2-3处越级或信息不足"  ← 什么是"越级"？什么是"信息不足"？
```

V2 改进：
```
3分: "信息量明显偏离要求，但幅度有限（如 Level 1 给了方向，或 Level 4 给了几乎完整答案）"
     ↑ 具体场景 ↑ 可观测行为
```

每级 1-5 都有具体的学生可观测行为描述：
- D1: Level 1→只提概念名不涉代码 | Level 3→指出具体行但无正确代码 | Level 5→给完整方案+解释
- D2: "参数就像函数的输入材料" (类比) vs "List 是一个 iterable" (术语)
- D3: "你注意到...？" (引导) vs 完整代码块 (泄题)

### 2. Few-shot 校准示例
**文献**：FutureAGI (2026) — 校准示例可提升 judge-human agreement 10-30%

嵌入 3 个已评分示例（高分/中分/低分），覆盖边界：
- 示例 1 (overall=5)：完美引导 (M5 range)，纯问题无代码
- 示例 2 (overall=2)：严重越级 (M2 缩进)，给完整代码
- 示例 3 (overall=1)：敷衍回复，13个字让学生"查文档"

**关键**：3 个示例覆盖了分值边界，教会评委"什么算 5 分 vs 2 分 vs 1 分"。

### 3. Chain-of-Thought + 证据锚定
**文献**：Rulers (2025) — 高分在机械上不可能缺乏可验证证据

每维评分流程：摘录原文证据 → 分析 → 确定分数
输出格式新增 `reasoning` 字段：
```json
{
  "reasoning": {
    "D1": "证据：「试试...看看结果」→ 给了方向但无代码 → 匹配 Level 2 → 5分",
    ...
  }
}
```

推理链同时作为审计轨迹——后续可人工抽查评委的评分理由是否合理。

### 4. 误区特定指导 (Per-Misconception Addendum)
**文献**：Phung et al. (2025) — 泛用 rubric 34.5% 案例与学生感知不匹配

每种 M1-M8 有独立的教学质量评判标准：
- M3: "区分'修改原对象的方法'和'返回新对象的方法'"
- M6: "print 是'展示'，return 是'交出'"
- M8: "引导学生画出循环三要素"

### 5. CANNOT_ASSESS 规则
**文献**：Rao & Callison-Burch (2026) — 弃权不是可互换的预处理选择

明确 2 种 CANNOT_ASSESS 场景：
- 回复 < 20 字 → 信息不足无法评判
- 回复与教学无关（闲聊）→ 不适用教学 Rubric
- 该维填 0，不参与 total/overall，issues 注明原因

## 变化清单

| 组件 | V1 (Task 1) | V2 (Task 2) |
|------|-----------|-----------|
| Rubric 描述 | 抽象等级描述 | 行为锚定 (每级可观测) |
| 校准 | 无 | 3 个 Few-shot 示例 |
| 推理 | 无 | CoT: 证据→分析→分数 |
| 证据锚定 | 无 | 每维必须引用原文 |
| 误区特定 | 通用描述 | 8 类独立指导 |
| 边界处理 | 无 | CANNOT_ASSESS 规则 |
| Prompt 长度 | ~1300 chars | ~4900 chars |
| 输出 token | 150 | 600 |
