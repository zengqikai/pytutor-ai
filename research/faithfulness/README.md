# R2 · AST 可验证的 LLM 解释忠实度基准

> 一句话：用**不会撒谎的 AST 当符号裁判**，量化 LLM 误区解释的忠实度，并检验
> 「AST 证据注入」的缓解效果。离线、零学生数据、复用项目现有双通道。

## 为什么这是一个"站得住脚"的本科科研点

本科层级能立住的贡献只有三类：数据集/基准、聚焦的实证发现、窄的方法增量。
"我搭了个系统"站不住；"我发现了 Z / 我构建了基准 W"才站得住。本方向同时提供：

1. **一个基准数据集**：每条 = (代码, 误区标签, 应有 AST 证据, LLM 解释, 忠实度标注)，
   含 hard negatives（结构接近误区但完全正确）。
2. **一个自动核验协议**：把 LLM 解释拆成原子断言，逐条对 AST 事实集核验，
   给出忠实度/幻觉率，并如实划出"不可核验"的意图类断言。
3. **三组实证发现**：C1 纯 LLM vs C2 AST 注入的忠实度差、幻觉类型分布、
   hard negative 上的假阳性模式。

**与已有工作的 delta（必须立住）**：不是"又一篇 faithfulness"，而是
"**符号化 AST 裁判 vs 纯文本裁判，用于编程误区诊断解释**"。动机有文献背书
（Mitton 2026：LLM 会幻觉误区、显式建模更优；McMining 附录：纯正确代码上的
系统性假阳性）。本项目的独特资产是**已经有对称双通道**（ast_features 符号证据
+ LLM 自然语言解释），改造成本极低。

**红线规避**：误区感知 tutor、裸 AST 增强诊断、多 agent 苏格拉底、答案泄露基准
均已被占（见研究计划文档 §2.2）。本方向刻意落在"用符号证据核验解释忠实度"
这一未被直接占领的窄口。

## 目录内容

| 文件 | 说明 |
|---|---|
| `ast_facts.py` | AST 事实集抽取器（纯 stdlib，可独立运行） |
| `faithfulness_verifier.py` | 忠实度核验器：断言拆分 + 逐条核验 |
| `dataset_seed.json` | 种子数据集（10 例，含 5 positive + 5 hard negative） |
| `run_experiment.py` | C1/C2 对比实验编排器（离线 demo + 真实 LLM 接入点） |
| `demo_results.json` | 桩 LLM 的离线演示结果（演示指标区分度，非真实模型） |

## 运行

```bash
# 1. 看事实抽取
python ast_facts.py

# 2. 看核验器区分"忠实 vs 含幻觉"解释
python faithfulness_verifier.py

# 3. 跑完整 C1 vs C2 对比（离线桩，可复现，可进 CI）
python run_experiment.py --demo --out demo_results.json

# 4. 真实实验：在 run_experiment.build_llm() 接入具体模型后
PYTUTOR_LLM_KEY=... python run_experiment.py --model deepseek --out real_results.json
```

## 8–10 周落地时间线（到 11 月初）

| 阶段 | 时长 | 内容 |
|---|---|---|
| 一 | 2–3 周 | 种子集扩到 150–200 条（含 hard negatives）；决定手工 vs LLM 生成+人工筛 |
| 二 | 2–3 周 | 完善断言拆分/核验（当前规则式已可跑，接 LLM 拆分器） |
| 三 | 2 周 | 跑 C1/C2(/C3) 对比；子实验 A（三通道假阳性）复用对抗集 |
| 四 | 2 周 | 人工抽查校验（1–2 人）确认自动判定与人一致；写作初稿 |

## 诚实的风险与对策

- 断言拆分用 LLM 会引入误差 → 人工抽查校验不可省；规则式拆分器作为确定性基线。
- AST 覆盖不了"意图类"断言 → 明确划出可核验/不可核验两类，只对可核验类计忠实度。
- 评测集若含 LLM 生成样本 → 生成模型与被测模型分离，防同源偏置。
